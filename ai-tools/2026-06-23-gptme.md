# gptme — 终端里随时召唤的本地 AI Agent

> 推送日期：2026-06-23
> 仓库：[gptme/gptme](https://github.com/gptme/gptme) · ⭐ 4.3k+ · Python · Apache-2.0
> 一句话：**"装在终端里的私人 AI 助手"** —— 凡是 shell 能去的地方（笔记本、SSH、tmux、headless 服务器、CI），它都能去。

---

## 1. 它解决的核心问题

主流编程 Agent（Claude Code、Cursor、Codex、Warp）几乎都是 **"绑定一个 IDE + 绑定一个厂商"** 的形态。这意味着：

- 必须在 GUI 里用，远程 SSH/服务器场景没法用；
- 模型供应商被锁死，换模型 = 换工具；
- "Agent" 本质上是 IDE 的一个面板，做不了**长跑型自治任务**（持续后台运行、跨天跨周完成事项）。

gptme 把这件事做反了——**Agent 是一等公民，编辑器只是其中一种载体**。它给出的形态是：

1. **纯命令行起家**：`gptme "把这个 bug 修了，跑通测试再 commit"` 一行起跑，无需 IDE。
2. **Provider-agnostic**：Anthropic / OpenAI / Gemini / xAI / DeepSeek / OpenRouter / 本地 `llama.cpp` 全部插拔，同一个 Agent 可以**按任务挑模型**（triage 用便宜模型，编码用 Claude/GPT 顶配）。
3. **持久化 Agent 模板**：通过 `gptme-agent-template` 一键孵化出一个有 journal、task 队列、lessons 记忆的"长期工作机器人"，可用 systemd/launchd 定时唤醒，**这是它和一次性 CLI 的本质区别**。

参考实现 [Bob](https://github.com/TimeToBuildBob) 自 2024 年底起 24×7 持续运行：自己提 PR、修 CI、维护任务队列、积累 lessons —— 这是目前**开源生态里最完整、跑得最久的自治 Agent 范例**之一。

## 2. 最核心的使用场景拆解

### 场景 A：远程/Headless 环境的全功能编码

这是 Cursor/Claude Code 完全覆盖不到的盲区。典型动作：

```bash
ssh prod-host
gptme "看一下 /var/log/app.log 里最近一小时的 5xx，找出可能的回归点"
```

为什么 gptme 在这里赢：

- 不依赖 GUI，**纯 stdio + 终端渲染**（diff 高亮、tab 补全、history）；
- 自带 `shell` / `ipython` / `tmux` / `patch` / `rag` 工具，相当于把 Claude Code 的核心能力打包进 `pip install`；
- `tmux` 工具能让模型**持有长生命周期会话**（编译跑 30 分钟的项目不会被卡死）；
- `subagent` 工具支持并行 / 隔离子任务，主 Agent 负责调度，子 Agent 干脏活。

### 场景 B：持久化自治 Agent（"养一只机器人"）

```bash
gptme-agent create ~/my-agent --name MyAgent
gptme-agent install        # 注册成 systemd timer / launchd
gptme-agent status         # 查看跑了什么、留下了什么
```

孵化出来的目录是个 **git 仓库**，包含：

```
my-agent/
├── journal/        # 每次唤醒写一条日记，模型自己读
├── tasks/          # YAML 任务队列，GTD 风格
├── knowledge/      # 长期记忆 / 知识库
├── lessons/        # 失败后总结出的"教训"，下次自动注入 prompt
└── gptme.toml      # 工具 / 插件 / MCP 配置
```

关键设计点：

- **记忆是文件，不是黑盒向量库**——可读可 diff 可 review，避免"Agent 越用越糊涂"；
- **Lessons system** 用关键字 + 工具 + 模式三维匹配，命中才注入到上下文，省 token；
- **Run loop** 既可定时（cron 风格），也可事件驱动（GitHub webhook、邮件、RSS）；
- **多 Agent 协作**有文件 lease + message bus + work claiming，避免两个 Agent 抢同一个任务。

### 场景 C：把现有 IDE 当外壳，仍然用 gptme 当大脑

```bash
pipx install 'gptme[acp]'
```

通过 **ACP (Agent Client Protocol)**，gptme 直接以 Coding Agent 身份接入 Zed、JetBrains。这条路线意味着：你可以**今天在 Cursor 里用 gptme，明天 SSH 到服务器还是同一只 gptme**——Agent 的人格、记忆、技能与编辑器解耦。

### 场景 D：MCP 工具集中心

`pipx install gptme` 默认带 MCP 支持，可以**动态发现 + 按需加载** MCP server。这意味着 gptme 可以做"MCP 路由器"：上百个 MCP 工具不会全部塞进上下文，模型问到再加载，从根本上避免了 MCP 多服务时上下文炸裂的问题。

## 3. 架构上值得抄的几点

1. **Tool feedback loop**：每个工具调用结果原样回喂模型，模型读到 stderr 后**自己 self-correct**，无需上层调度；这是它能跑长任务的基础。
2. **Lessons / Skills / Plugins / Hooks 四层扩展**：
   - Plugins：写 Python 包，定义工具/钩子；
   - Skills：纯 Markdown bundle（Anthropic Skills 兼容），关键字触发，**零代码扩展**；
   - Lessons：失败/成功经验，匹配命中才注入；
   - Hooks：生命周期事件（tool 前后、对话开始）注入逻辑。
   分层后用户可按"想多深就改多深"逐级介入，不会一上来就要写一个完整插件。
3. **Morph 工具 + patch 工具并存**：小改动用 `patch`，大段重写用 `morph`（fast-edit 模型），成本/质量自动平衡。
4. **Content-addressable storage**（v0.31）：对话/文件按内容寻址，跨 session 引用同一个产物不重复存。
5. **Cost tracking** 内建：每条对话精确成本可见，长跑 Agent 不会"用着用着突然账单爆炸"。

## 4. 上手最快路径

```bash
# 一行装上，自带 MCP
pipx install gptme

# 配模型（任挑一个）
export ANTHROPIC_API_KEY=...   # 或 OPENAI_API_KEY / OPENROUTER_API_KEY

# 试一把
gptme "用 curses 写个贪吃蛇，跑通为止"

# 想长期养一只
pipx install gptme-agent-template
gptme-agent create ~/bob --name Bob
gptme-agent install
```

> 进阶：把 `gptme.toml` 里的 `[plugins]` 打开，把团队的 best practice 写成 `lessons/*.md`，整支团队共享一份会"越用越聪明"的 Agent。

## 5. 适合 / 不适合的判断

✅ 适合：

- 重度终端 / 远程开发用户；
- 想跑**长期自治 Agent**（运维巡检、自动 PR review、定时报告）；
- 不想被单一模型厂商绑死；
- 想自己定制工具、记忆、流程的玩家。

❌ 不太适合：

- 只想要"IDE 里弹个 Chat 框"的轻度用户（Cursor 体验更顺手）；
- 完全不愿意碰命令行的人；
- 要求开箱即用的可视化看板（gptme 的 webui 还偏简洁）。
