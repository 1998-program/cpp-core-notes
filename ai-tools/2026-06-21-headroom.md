# Headroom — AI Agent 的上下文压缩层

> **项目**: [chopratejas/headroom](https://github.com/chopratejas/headroom)
> **Stars**: 39,600+ (截至 2026-06-21)
> **语言**: Python + Rust (maturin 构建)
> **协议**: Apache 2.0
> **最新版本**: v0.26.0

---

## 一句话概括

Headroom 在你的 AI 应用和 LLM 之间插入一个本地透明压缩层，把工具输出、日志、RAG 检索结果、代码文件等在送达大模型之前先压缩掉 60-95% 的 Token，同时保持回答质量不变。

---

## 诞生故事

Netflix 高级工程师 Tejas Chopra 在一次个人项目中收到了 287 美元的 API 账单，分析后发现大量成本并非来自他写的 Prompt，而是自动生成的冗余数据——嵌套 JSON、重复 API 响应、多余数据库字段。研究显示 AI 应用中约 **76% 的 Token 消耗仅用于读取输入**。2026 年 1 月开源后一直不温不火，直到 6 月初突然在国内外 AI 圈爆火，目前已累计帮用户节省约 **70 万美元**成本，释放超过 **2000 亿个 Token**。

## 核心架构

```
你的 Agent / 应用 (Claude Code, Cursor, Codex, 自研代码…)
    │ prompts · tool outputs · logs · RAG results · files
    ▼
┌──────────────────────────────────────────────────────┐
│  Headroom (本地运行 — 数据不出本机)                    │
│  ─────────────────────────────────────────────────── │
│  CacheAligner → ContentRouter → CCR                  │
│  ├─ SmartCrusher (JSON)                              │
│  ├─ CodeCompressor (AST)                             │
│  └─ Kompress-base (文本, HuggingFace)                │
│                                                      │
│  Cross-agent memory · headroom learn · MCP           │
└──────────────────────────────────────────────────────┘
    │ compressed prompt + retrieval tool
    ▼
LLM 提供商 (Anthropic · OpenAI · Bedrock · …)
```

### 关键组件

| 组件 | 职责 |
|------|------|
| **ContentRouter** | 检测内容类型，自动选择最优压缩算法 |
| **SmartCrusher** | 专攻 JSON — 压缩数组、嵌套对象、混合类型 |
| **CodeCompressor** | AST 感知压缩，支持 Python/JS/Go/Rust/Java/C++ |
| **Kompress-base** | 开源文本压缩模型 (HuggingFace)，在真实 Agent 轨迹上微调 |
| **CacheAligner** | 稳定 Prompt 前缀，让提供商 KV Cache 真正命中 |
| **CCR** | 压缩-缓存-检索机制，原始内容本地缓存，LLM 按需取回 |
| **IntelligentContext** | 基于学习重要性评分的上下文窗口适配 |

核心直觉：剥离噪声让模型更聚焦于信号，部分场景反而提升精度。

## 四种接入方式

### 1. 一行命令包装现有 Agent

```bash
headroom wrap claude    # Claude Code
headroom wrap codex     # Codex CLI
headroom wrap cursor    # Cursor
headroom wrap aider     # Aider
headroom wrap copilot   # GitHub Copilot CLI
```

### 2. 本地代理 — 零代码改动

```bash
headroom proxy --port 8787
# 然后设置环境变量
export ANTHROPIC_BASE_URL=http://localhost:8787
export OPENAI_BASE_URL=http://localhost:8787/v1
```

任何 OpenAI 兼容客户端自动走压缩通道。

### 3. 库调用 — Python / TypeScript

```python
from headroom import compress

result = compress(messages, model="claude-sonnet-4-5")
response = client.messages.create(
    model="claude-sonnet-4-5",
    messages=result.messages
)
print(f"Saved {result.tokens_saved} tokens ({result.compression_ratio:.0%})")
```

```typescript
import { compress } from 'headroom-ai';
const result = await compress(messages, { model: 'gpt-4o' });
```

### 4. MCP 服务器模式

```bash
headroom mcp install
```

提供三个 MCP 工具：`headroom_compress`、`headroom_retrieve`、`headroom_stats`，任何 MCP 客户端均可调用。

## 核心使用场景深度分析

### 场景一：AI 编程助手的日常 Token 开销优化

**痛点**: Claude Code / Cursor 等工具在大型代码库中搜索 Bug 时，一次调试可能读取多个完整文件（含大量无关代码）、翻看长篇日志、检索 RAG 文档、保留多轮对话历史，轻松消耗 3-8 万 Token。每天跑几十次就是每月几百美元。

**Headroom 的解法**: `headroom wrap claude` 一行命令，自动压缩所有工具输出。SmartCrusher 精简 JSON 结构，CodeCompressor 只保留 AST 关键节点，Kompress-base 压缩日志摘要。CCR 保证原始数据随时可回溯。

**效果**: 代码搜索场景 Token 降 92%，日常编程辅助成本砍半以上，且不需要改任何代码或工作流。

### 场景二：SRE / 运维团队的事故调试

**痛点**: 事故发生时需要让 LLM 分析数千行日志、API 响应、监控指标。这些数据体积巨大但信号稀疏——1000 行日志里可能只有 1 行是 FATAL。

**Headroom 的解法**: ContentRouter 自动识别日志类型，SmartCrusher 压缩结构化监控数据，Kompress-base 提取日志中的关键事件。实测 65,694 Token → 5,118 Token，省 92%。

**效果**: 同样的 Token 预算可以分析 10 倍以上的日志量，事故响应更快；或者同样的分析量只用 1/10 的 API 费用。

### 场景三：多 Agent 协作中的上下文传递

**痛点**: 多个 Agent（如 Claude Code + Codex + Gemini）各自产生大量中间结果，相互传递时上下文爆炸。每个 Agent 都要把前序 Agent 的完整输出读进来。

**Headroom 的解法**: Cross-agent memory 共享压缩存储，Agent 写入的事实自动去重。`headroom learn` 挖掘失败会话，自动写修正到 CLAUDE.md / AGENTS.md / GEMINI.md。SharedContext 在多 Agent 工作流间传递压缩后的上下文。

**效果**: 跨 Agent 协作的上下文开销大幅降低，避免重复传输相同信息，Agent 间"记忆"自动同步。

### 场景四：RAG 管道的检索结果压缩

**痛点**: RAG 检索返回多个文档片段，很多是重复或低相关的，全部喂给 LLM 浪费 Token 且引入噪声。

**Headroom 的解法**: Kompress-base 在嵌入检索后、送入 LLM 前对检索结果压缩。IntelligentContext 基于重要性评分筛选和排序上下文片段。CCR 保留原始文档，LLM 需要细节时可按需取回。

**效果**: RAG 管道的 Token 开销降 60-80%，且精度不降反升（噪声减少让模型更聚焦）。

## 安装

```bash
pip install "headroom-ai[all]"

# 按需安装子模块
pip install "headroom-ai[proxy]"    # 代理模式
pip install "headroom-ai[mcp]"      # MCP 服务器
pip install "headroom-ai[ml]"       # Kompress-base 模型
pip install "headroom-ai[code]"     # AST 代码压缩
pip install "headroom-ai[memory]"   # 跨 Agent 记忆
```

需要 Python 3.10+。Rust 核心通过 maturin 编译，企业 SSL 检查环境需预装 Rust。

---

## 注意事项

1. **纯文本日志压缩效果有限**: 第三方评测显示，对非结构化的自由文本日志，ContentRouter 可能无法路由到合适的压缩器，节省率为 0%。SmartCrusher 对结构化 JSON 效果最好。
2. **企业 SSL 环境**: pip 安装可能因 SSL 检查失败，需预装 Rust 工具链或使用 `--only-binary` 安装预编译包。
3. **代理模式延迟**: 本地压缩耗时毫秒级，但整体端到端可能因代理转发引入少量延迟。对长上下文场景，Token 节省带来的 API 调用加速通常远大于压缩开销。
4. **早期项目**: 版本号 v0.26.0，API 可能有变动。生产环境建议先用 library 模式在 JSON/结构化数据上试点。

## 总结

Headroom 解决了一个 2026 年 AI 工程化中最实际的问题：**你付给 LLM 的钱，大部分花在了让它读废话上**。它不是又一个 Prompt 优化框架，而是在 Agent 和 LLM 之间插入一层透明的压缩管道——自动检测内容类型、选择最优算法、保留原始数据可回溯、跨 Agent 共享记忆。一行 `headroom wrap claude` 就能立竿见影地砍掉 60-95% 的 Token 消耗，且精度不降。

对于每天都在用 Claude Code / Cursor / Copilot 的开发者，以及需要处理大量日志和 API 响应的 SRE 团队，Headroom 是目前最成熟的 Token 压缩方案。
