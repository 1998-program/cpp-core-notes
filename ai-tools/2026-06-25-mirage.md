# Mirage — 给 AI Agent 的统一虚拟文件系统

> **Repo**：[strukto-ai/mirage](https://github.com/strukto-ai/mirage) · **Stars**：⭐3.2k+ · **License**：MIT
> **官网/文档**：<https://docs.mirage.strukto.ai>
> **生态**：Python (`mirage-ai`)、TypeScript (`@struktoai/mirage-node` / `-browser` / `-agents`)、CLI (`mirage`)
> **日期**：2026-06-25

## 一句话

把 S3、Google Drive、Gmail、Slack、Notion、Postgres、Redis、SSH …… 这一堆原本要靠 N 个 SDK 和 M 个 MCP Server 才能访问的服务，**全部挂载成同一棵文件系统**——任何会写 bash 的 LLM，开箱即可 `grep / cat / cp / find / pipe`，零新词汇。

## 它真正解决的问题

当下 Agent 接外部数据有三条主流路径，每条都有硬伤：

| 方案 | 问题 |
|------|------|
| 给 LLM 写 N 个 Tool/Function | Tool 多到上下文爆炸；每接一个新源都要写新 schema、新 prompt 例子 |
| 接 N 个 MCP Server | 每个 server 一套独立语义，跨源 pipeline（"把 S3 上的 csv 拷到本地再 grep"）几乎做不到 |
| 让 Agent 直接调 SDK | 模型要记每个 SDK 的 API；权限、缓存、快照都得自己重新发明 |

**Mirage 的思路**：所有外部资源 = 文件系统挂载点。

```python
ws = Workspace({
    "/data":   RAMResource(),
    "/s3":    S3Resource(S3Config(bucket="logs")),
    "/slack": SlackResource(token=...),
    "/gmail": GmailResource(...),
})

# LLM 生成的就是普通 shell：
await ws.execute("grep -r alert /slack/channels/general/ | wc -l")
await ws.execute("cp /s3/report.csv /data/local.csv")
await ws.execute("wc -l $(find /s3/data -name '*.jsonl')")
```

LLM 早已把 "bash 文件系统" 这套语义吃透了——**复用模型已有的能力，而不是教它新词**，这是 Mirage 最锋利的一刀。

## 核心使用场景

### 场景一：给 Coding Agent 一套"远程电脑"

Claude Code / Codex / OpenCode / Pi 这类编码 Agent 本来只能动本地磁盘。挂上 Mirage 后：

```bash
mirage workspace create ws.yaml --id dev
# ws.yaml 把 GitHub repo、Linear issue、S3 制品全挂上
```

Agent 在 `dev` 这个 workspace 里 `ls /github/myrepo/issues`、`cat /linear/PROJ-123` 就和操作本地一样自然。需要复现 bug 时，`mirage workspace snapshot dev demo.tar`，把整个上下文发给同事，对方 `mirage workspace load` 就拿到一模一样的环境——**Agent 运行态变得像 Docker image 一样可分发**。

### 场景二：跨数据源的临时 ETL，不再起 Airflow

最典型的"小聚合"场景：把 Slack 报警总数、S3 里的事件日志、Postgres 里的工单条数对一对。过去要写三段代码 + 一个胶水脚本，现在一行：

```bash
echo "slack=$(grep -r alert /slack/channels/oncall/ | wc -l) \
      s3_events=$(wc -l < /s3/events/2026-06-24.jsonl) \
      tickets=$(cat /pg/public/tickets/count.json)"
```

Agent 不需要关心每家服务的鉴权和分页，**这些被 Resource 实现层吃掉了**。

### 场景三：把"自定义 reader"做成 per-resource × per-filetype 的覆写

Mirage 允许重载文件系统命令，例如让 `cat` 在 S3 上遇到 Parquet 时直接渲染成 JSON 行：

```typescript
ws.command('cat', { resource: 's3', filetype: 'parquet' }, customParquetReader)
ws.command('summarize', mySummarizer)

await ws.execute('cat /s3/events/2026-05-06.parquet | jq .user')
await ws.execute('summarize /data/local.csv')
```

这相当于把 LangChain 那套 "DocumentLoader / Retriever / Tool" 的概念，**全部下沉到文件读路径**——LLM 看到的依然是 `cat | jq`，不需要学新 API。

### 场景四：嵌入 FastAPI / Express，做"Agent 后端"

Python / TS SDK 都是纯进程内库，不像 MCP 还要起 sidecar。一个 FastAPI 服务里：

```python
@app.post("/run")
async def run(cmd: str):
    return await ws.execute(cmd)
```

就把整个 Workspace 暴露成 HTTP，前端 Agent UI 直接拿来用。**没有额外进程、没有额外协议**。

## 架构上值得记的几点

1. **Workspace = 多个 Resource 的根挂载**。每个 Resource 实现一组 POSIX 操作（`list / read / write / delete …`），Resource 之间通过路径前缀隔离。
2. **命令是可插拔的**。`grep / cat / find / wc` 这些是 Mirage 自带的"用户态 coreutils"，但你可以新增 `summarize` 这种 LLM 命令，或对某个 (resource, filetype) 组合覆写默认实现。
3. **两层缓存默认开**：
   - **Index cache**：listing/metadata，TTL 默认 10 分钟。
   - **File cache**：对象字节，默认 512MB RAM。
   - 想跨进程共享？换成 `RedisFileCacheStore`，几行配置即可水平扩展。
4. **Snapshot / Clone / Version**：整个 workspace 可以打 tar、跨机器恢复。这让"Agent 实验复现"从玄学问题变成了 `git clone` 一样的事。
5. **约 50 个内置后端**：RAM / Disk / Redis / S3 / R2 / OCI / Supabase / GCS / Gmail / GDrive / GDocs / GSheets / GSlides / GitHub / Linear / Notion / Trello / Slack / Discord / MongoDB / Postgres / LanceDB / Qdrant / SSH ……

## 与 MCP 的关系

不是替代，更像**正交补位**：

- MCP 解决的是"LLM 怎么发现 / 调用工具"的协议问题；
- Mirage 解决的是"工具背后的资源如何统一寻址、如何组合"的数据层问题。

实际上你可以同时用：让 LLM 通过 MCP 看到一个 `mirage_execute(cmd)` 工具，Mirage 内部再去访问 S3 / Slack / Gmail。这样 MCP 只暴露 1 个工具，但 LLM 拿到的能力是 50 个后端的笛卡尔积。

## 安装与上手

```bash
# Python
uv add mirage-ai

# TypeScript (Node)
npm install @struktoai/mirage-node

# CLI
curl -fsSL https://strukto.ai/mirage/install.sh | sh
# 或 npx @struktoai/mirage-cli / uvx mirage-ai
```

最小例子（Python）：

```python
from mirage import Workspace
from mirage.resource.ram import RAMResource
from mirage.resource.s3 import S3Config, S3Resource

ws = Workspace({
    "/data": RAMResource(),
    "/s3":   S3Resource(S3Config(bucket="my-bucket")),
})

await ws.execute("cp /s3/report.csv /data/report.csv")
await ws.execute("grep alert /s3/data/log.jsonl | wc -l")
await ws.snapshot("demo.tar")     # 把整个工作空间打包带走
```

## 适合在什么时候掏出来

- 在做**多源数据 Agent**（客服分析、运维 oncall、内部知识问答）；
- 给**编码 Agent 配长期工作环境**，需要可快照、可分享；
- 想砍掉一堆**临时 ETL 脚本和粘合代码**；
- 想给团队提供一个**统一的"Agent 沙箱"接口**，避免每个项目重造 Tool 层。

不太适合：单一数据源、纯结构化 SQL 场景（直接接库即可）、或对 sub-ms 时延敏感的在线链路。

## 一句话收尾

**别再教 LLM 学新 SDK 了——把世界挂成文件系统，让它继续 `grep`。**
