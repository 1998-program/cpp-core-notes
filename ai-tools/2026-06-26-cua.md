# Cua — 给 AI Agent 一台真正能用的电脑

> 仓库：[trycua/cua](https://github.com/trycua/cua) · 18.9k★ · MIT · Python/Swift
> 一句话：让 AI Agent 像人一样使用一台完整的电脑——看屏幕、点按钮、敲键盘、跑 shell——还不抢你的鼠标焦点。
> 推送日期：2026-06-26

---

## 1. 它到底解决什么问题？

绝大多数 AI Agent 框架（LangChain、AutoGen、CrewAI）解决的是「让 LLM 调用 API/工具」。但很多真实工作并没有 API：
打开本机的 Figma 改一张图、在公司内网 ERP 里录单、跨网页和 PDF 之间复制粘贴、给一台没有 SDK 的老 Windows 软件做回归测试……这些任务唯一稳定的「通用接口」就是**屏幕 + 鼠标 + 键盘**。

Cua 把这件事工程化：
- 给 Agent **一个隔离的、随取随用的计算机环境**（沙箱：Linux/macOS/Windows/Android，本地 QEMU 或云端）；
- 给 Agent **一套统一的「看 + 操作」API**（截图、点击、键盘、shell、多点触控）；
- 给「使用宿主机本机」的场景一个**后台驱动**（Cua Driver），让 Agent 操作不打断真人。

它不是又一个 Agent 框架，**它是 Agent 与电脑之间的那一层「驱动 + 沙箱 + 评测」基础设施**。

## 2. 核心架构：四件套各司其职

```
┌─────────────────────────────────────────────────────────────┐
│  你的 Agent（Claude / Codex / Cursor / OpenClaw / 自定义）    │
└───────────────┬─────────────────────────────┬───────────────┘
                │ MCP / SDK                   │ SDK
                ▼                             ▼
        ┌──────────────┐              ┌──────────────────┐
        │  Cua Driver  │              │   Cua Sandbox    │
        │  操作本机桌面  │              │  一次性 VM/容器   │
        │（不抢焦点）   │              │  Linux/Win/macOS │
        └──────┬───────┘              └──────┬───────────┘
               │                             │
               ▼                             ▼
        ┌──────────────┐              ┌──────────────────┐
        │  Lume (mac)  │              │  Cua-Bench       │
        │  Apple Vz    │              │  OSWorld 等评测   │
        └──────────────┘              └──────────────────┘
```

四个组件可以独立使用：

| 组件 | 用途 | 用户 |
| --- | --- | --- |
| **cua (SDK)** | 一次性沙箱：`Sandbox.ephemeral(Image.linux())` 即起即用 | 给 Agent 一个干净环境做事 |
| **cua-driver** | 在你**正在用的电脑**上后台操作 GUI，**不抢鼠标焦点** | Claude Code、Cursor、Codex 等的桌面执行后端 |
| **cua-bench** | OSWorld / ScreenSpot / Windows Arena 等评测集，可导出轨迹做 RL | 训练/评测 computer-use 模型 |
| **lume** | Apple Silicon 上原生 macOS/Linux 虚拟化（Apple Vz.framework） | 本地 macOS 沙箱底层 |

## 3. 最核心的使用场景：三类典型用法

### 场景 A：「给 Agent 一台一次性电脑」做不可逆任务

这是 Cua 最被低估、也最值得用的场景。当你让 Agent 跑「在 Excel 里做数据透视」「在浏览器里下载 100 个发票」时，你**绝对不希望它跑在你的本机**——一个误操作可能把 Chrome 书签清掉。

```python
from cua import Sandbox, Image

async with Sandbox.ephemeral(Image.linux()) as sb:
    # 进入沙箱执行任何危险/脏活
    await sb.shell.run("apt-get install -y libreoffice")
    await sb.files.upload("./data.csv", "/root/data.csv")

    # Agent 视觉操作
    screenshot = await sb.screenshot()        # 给 VLM 看
    await sb.mouse.click(720, 380)            # VLM 决策后回传
    await sb.keyboard.type("=SUMPRODUCT(...)")

    # 取产物，沙箱销毁
    await sb.files.download("/root/out.xlsx", "./out.xlsx")
# 上下文一退出，VM 整个销毁，无任何残留
```

关键设计：**一套 API 跨 Linux/macOS/Windows/Android，跨本地 QEMU 和云端 cua.ai**。Agent 代码不变，部署位置可换。

### 场景 B：「Cua Driver」让 Agent 在你工作时悄悄操作你的桌面

```bash
# 让 Claude Code 拥有桌面操作能力，但不抢你的鼠标
claude mcp add --transport stdio cua-driver -- cua-driver mcp
```

之后你跟 Claude 说「帮我把刚才那张 Figma 导出成 PNG 放到 Desktop」，
它会在**后台进程**调用 Cua Driver，**不会移动你正在用的真实鼠标**——
这一点是绝大多数 PyAutoGUI/AppleScript 类方案做不到的。

技术上 Cua Driver 在 macOS 上走的是 CoreGraphics 的「事件源 + 不抢焦点」路径；
Windows 上是 UI Automation + 后台消息注入；Linux 走合成器协议。
这是把「桌面 Agent」从玩具变成生产力工具的关键工程点。

### 场景 C：「Cua-Bench」评测/训练 computer-use 模型

```bash
cb run dataset datasets/cua-bench-basic --agent cua-agent --max-parallel 4
```

它把 OSWorld 这类公开 benchmark 包成一行命令，并且自动导出**操作轨迹**（screenshot + action 序列），
直接拿来给 VLM/RL 训练。对想做「自家行业的 computer-use 模型」的人，这是最省力的数据飞轮起点。

## 4. 它和「相似项目」差在哪？

| 项目 | 定位 | 与 Cua 差异 |
| --- | --- | --- |
| **E2B** | 给 LLM 一个 Python 解释器沙箱 | E2B 强于代码执行/无 GUI；Cua 强于**带 GUI 的整机** |
| **OpenInterpreter** | 在本机直接执行代码 | 没有隔离层；Cua 关注「沙箱 + GUI 多 OS」 |
| **Anthropic Computer Use** | Claude 内置截图+点击工具 | 只能用 Claude；Cua 是**模型无关**的执行层 |
| **PyAutoGUI / AppleScript** | 桌面自动化老兵 | 会抢焦点、跨 OS 痛苦、无沙箱 |
| **Selenium / Playwright** | 浏览器自动化 | 只覆盖浏览器，桌面 App 无能为力 |

Cua 的差异化非常清晰：**模型无关 + 跨 OS 一致 API + 真后台驱动 + 自带评测集**。这四件凑齐的目前只有它。

## 5. 工程上几个值得抄的点

1. **`Sandbox.ephemeral` + `async with` 语义**：把「VM 生命周期」绑到 Python 作用域上，比手动 create/destroy 优雅得多。Agent 框架做资源管理可以抄这种 API 形态。
2. **同一套接口跨 cloud / local QEMU / Apple Vz**：上层 SDK 不暴露任何 hypervisor 差异。做多端 SDK 的可以学这种 dispatcher。
3. **MCP 作为「桌面驱动」的传输层**：Cua Driver 默认是一个 MCP server，意味着任何支持 MCP 的客户端（Claude Code / Cursor / Codex / OpenClaw）零改造接入。这是把「专用工具」变成「生态插件」的标准做法。
4. **Lume 直接调 Apple Vz.framework**：相比 UTM/Parallels 拉满便携性和速度，Apple Silicon 上启动 macOS VM 比 Docker 还快——这是 macOS 沙箱方案的天花板。

## 6. 上手 5 分钟路径

```bash
# A. 只想给 Agent 一个 Linux 沙箱
pip install cua
python -c "
import asyncio
from cua import Sandbox, Image
async def main():
    async with Sandbox.ephemeral(Image.linux()) as sb:
        print(await sb.shell.run('uname -a'))
asyncio.run(main())
"

# B. 想让 Claude Code / Cursor 能操作你的 mac/Windows 桌面
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/trycua/cua/main/libs/cua-driver/scripts/install.sh)"
claude mcp add --transport stdio cua-driver -- cua-driver mcp

# C. 想跑 computer-use benchmark
git clone https://github.com/trycua/cua && cd cua/cua-bench
uv tool install -e . && cb image create linux-docker
cb run dataset datasets/cua-bench-basic --agent cua-agent --max-parallel 4
```

## 7. 我的判断

`computer-use` 是 2026 这一波 Agent 真正的「最后一公里」——
**LLM 智能再强，没有「能用电脑」的执行层，就只能在 chat 框里聊。**

Cua 的价值在于它把这一层做成了**三件可独立使用的基础设施**（沙箱 / 驱动 / 评测），并且模型无关。
做企业级 Agent 落地、做桌面自动化产品、做 computer-use 模型训练，都能在它身上至少省下 2-3 个月的工程。

如果你正在写一个「能干活的 Agent」而不是「能聊天的 Agent」，Cua 是绕不开的一块拼图。
